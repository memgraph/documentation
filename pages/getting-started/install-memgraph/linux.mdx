# Install Memgraph on Linux

Install Memgraph natively on Linux from a DEB or RPM package and run it as a
systemd service. Since Memgraph 3.13, there is one DEB package and one RPM
package per architecture (x86_64 and ARM64), not one per distribution. They
run on any Linux distribution with glibc 2.31 or newer.

| Distribution family | Package |
|---|---|
| Debian, Ubuntu and other distributions that use `apt` | DEB |
| Red Hat Enterprise Linux, CentOS, Rocky Linux, Fedora and other distributions that use `dnf` | RPM |

To check your glibc version, run:

```bash
ldd --version
```

The packages also need Python 3.10 or newer on the host. On
distributions whose default `python3` is older, such as CentOS 9, the package
installs and uses a newer Python interpreter.

To install on Windows, see [Install Memgraph on Windows with
WSL](/getting-started/install-memgraph/wsl). To run Memgraph in a container,
see [Docker](/getting-started/install-memgraph/docker).

<Callout type="warning">
Storage snapshots from one Memgraph version might not load in another. Before
you install a newer version over an existing one, follow
[Upgrades](/database-management/upgrades).
</Callout>

## Install the DEB package on Debian or Ubuntu

Download the DEB package, then install it with `dpkg`.

<Steps>

{<h3 id="download-the-deb-package" className="custom-header">Download the DEB package</h3>}

Download the package from the [Memgraph Download
Hub](https://memgraph.com/download/) or with a link from [direct download
links](/getting-started/install-memgraph/direct-download-links). For example,
the x86_64 package:

<CodeSnippet code="sudo wget https://download.memgraph.com/memgraph/v3.14.0/x86_64-deb/memgraph_3.14.0-1_amd64.deb" page="install-memgraph/linux" os="deb"/>

For the ARM64 package, the system allocator build or a newer version, take the
link from [direct download
links](/getting-started/install-memgraph/direct-download-links) and use its
file name in the next step.

{<h3 id="install-the-deb-package" className="custom-header">Install the DEB package</h3>}

Install the package with `dpkg`:

```bash
sudo dpkg -i ./memgraph_3.14.0-1_amd64.deb
```

If `sudo` isn't installed or `dpkg` reports dependency problems, see
[Troubleshooting](#troubleshooting).

</Steps>

When the package is installed, [start Memgraph](#start-memgraph).

## Install the RPM package on CentOS, Fedora, Rocky Linux or Red Hat

Download the RPM package, then install it with `dnf`.

<Steps>

{<h3 id="download-the-rpm-package" className="custom-header">Download the RPM package</h3>}

Download the package from the [Memgraph Download
Hub](https://memgraph.com/download/) or with a link from [direct download
links](/getting-started/install-memgraph/direct-download-links). For example,
the x86_64 package:

<CodeSnippet code="sudo wget https://download.memgraph.com/memgraph/v3.14.0/x86_64-rpm/memgraph-3.14.0_1-1.x86_64.rpm" page="install-memgraph/linux" os="rpm"/>

For the ARM64 (aarch64) package, the system allocator build or a newer version,
take the link from [direct download
links](/getting-started/install-memgraph/direct-download-links) and use its
file name in the next step.

{<h3 id="install-the-rpm-package" className="custom-header">Install the RPM package</h3>}

Install the package with `dnf`:

```bash
sudo dnf install -y ./memgraph-3.14.0_1-1.x86_64.rpm
```

On Red Hat Enterprise Linux, SELinux can block Memgraph's access to system
resources. See [SELinux blocks Memgraph](#selinux-blocks-memgraph).

</Steps>

When the package is installed, [start Memgraph](#start-memgraph).

## Start Memgraph

Start Memgraph as a service. If it's already running, the command does
nothing:

```bash
sudo systemctl start memgraph
```

To check that Memgraph is running, read its log:

```bash
sudo journalctl --unit memgraph
```

The log contains a line like this:

```plaintext copy=false
You are running Memgraph vX.X.X
```

To check the state of the service:

```bash
sudo systemctl status memgraph
```

To start Memgraph automatically when the machine boots:

```bash
sudo systemctl enable memgraph
```

## Connect to Memgraph

To [run queries](/querying) from the terminal, install
[`mgconsole`](/getting-started/cli). You can also connect with one of the
[client libraries](/client-libraries) or with [Memgraph Lab](/memgraph-lab), the
visual user interface.

## Configure Memgraph

The configuration file is `/etc/memgraph/memgraph.conf`. For all options, see
[Configuration](/database-management/configuration). Memgraph reads the file on
startup, so restart it after you change the file:

```bash
sudo systemctl restart memgraph
```

If Memgraph runs out of memory map areas on large workloads, [increase the
`vm.max_map_count`
parameter](/database-management/system-configuration#increasing-memory-map-areas).

## Stop Memgraph

```bash
sudo systemctl stop memgraph
```

## Troubleshooting

The problems below can come up during or after installation. If yours isn't
listed, ask on [Discord](https://discord.gg/memgraph).

### sudo is not installed on Debian

If Debian reports the following error:

```plaintext copy=false
-bash: sudo: command not found
```

install `sudo` as the root user:

```bash
apt update -y
apt install sudo -y
```

### dpkg reports dependency problems

If `dpkg -i` ends with an error like this:

```plaintext copy=false
dpkg: error processing package memgraph (--install): dependency problems -
leaving unconfigured Errors were encountered while processing: memgraph
```

some of the package's dependencies are missing. Update the package lists, then
let `apt` install the missing dependencies and finish installing Memgraph:

```bash
sudo apt update
sudo apt-get install -f
```

### Python libraries for query modules are missing

Since Memgraph 3.13, the package installs the Python libraries that the bundled
query modules use, including [NumPy](https://numpy.org/),
[SciPy](https://www.scipy.org/) and [NetworkX](https://networkx.org/), during
installation. The machine needs network access at install time.

If that step was skipped (`MG_SKIP_PYTHON_DEPS=1`) or failed, Memgraph prints a
note like this on startup:

```plaintext copy=false
You are running Memgraph v3.14.0
To get started with Memgraph, visit https://memgr.ph/start
NOTE: Please install networkx, numpy, scipy to be able to use proxied NetworkX algorithms. E.g., CALL nxalg.pagerank(...).
```

Install the libraries as the `memgraph` user, because Memgraph's embedded
Python interpreter runs as that user and only sees its environment:

```bash
sudo runuser -l memgraph -c 'python3 -m pip install --user networkx numpy scipy'
```

If you don't use the query modules that need these libraries, you can ignore
the note.

### SELinux blocks Memgraph

Red Hat Enterprise Linux uses SELinux (Security-Enhanced Linux) to enforce
mandatory access control: each program can reach only the resources its policy
allows. In a [high
availability](/database-management/clustering/high-availability) deployment,
check the SELinux policies if the instances can't see each other. Even with the
firewall open, you might need to disable SELinux, as the [networking
configuration](/deployment/best-practices#networking-configuration) best
practices describe.
