# Context Graph

Context Graph gives your coding agents a memory that lasts across sessions and
is shared between agents. It records each session of Claude Code, Codex, GitHub
Copilot CLI, Cursor, OpenCode, Antigravity CLI or Grok Build as a graph in
Memgraph: your prompts, the agent's replies, the tools it called, the skills it
used and the memories it saved. In the next session, any of those agents can
recall it.

Context Graph is open source and part of the
[Memgraph AI Toolkit](https://github.com/memgraph/ai-toolkit/tree/main/context-graph).
It runs on your machine by default, with no account or cloud service, and
[redacts secrets](/ai-ecosystem/ai-memory/context-graph/configuration#keep-secrets-out-of-the-graph)
before anything is stored.

## What your agents get

After setup, every connected agent gets three things:

- **Capture.** Hooks in the agent write each session to the graph as it
  happens. You use the agent as before.
- **Recall.** A `recall` tool, served over the Model Context Protocol (MCP),
  finds what your past sessions hold about a question. A session also starts
  with a short note on where you left off in the current project, whichever
  agent you used last.
- **Memory.** If you turn it on, a `memory` tool replaces the agent's own
  memory. The memories the agent saves are stored in the graph and shared by
  all your agents.

See [Recall and memory](/ai-ecosystem/ai-memory/context-graph/recall-and-memory)
for how each one works.

## How the graph is organized

Each session is a `Session` node, linked to its `User`. Everything recorded in
the session hangs off that node, so one Cypher query can span all of it:

```plaintext copy=false
(:User)-[:HAD_SESSION]->(:Session)
                         ├─[:HAS_ACTION]->(:Action)          prompts, replies, tool calls and results
                         ├─[:USED_SKILL]->(:Skill)           agent skills the session used
                         └─[:PRODUCED_MEMORY]->(:Memory)     memories the agent saved
(:User)-[:HAS_MEMORY]->(:Memory)
```

These are the three types of [AI memory](/ai-ecosystem/ai-memory): `Memory`
nodes are semantic memory, `Action` nodes are episodic memory and `Skill`
nodes are procedural memory.

Context Graph can also extract the people, projects, files and decisions your
sessions mention into a [knowledge graph](/ai-ecosystem/ai-memory/context-graph/knowledge-graph),
linked back to the sessions that mention them. Recall uses it to find facts
across sessions.

## Components

Context Graph is a set of Python packages. Setup installs the ones you need,
so you only need this list to change what is recorded or to use a package in
your own application.

| Package | What it records or does |
| --- | --- |
| `memgraph-context-graph` | The `memgraph-context-graph` command: setup, the hooks, the MCP server and the configuration. |
| `actions-graph` | Prompts, replies, tool calls and tool results, as `Action` nodes. |
| `skills-graph` | The agent skills a session used, as `Skill` nodes. |
| `sessions-graph` | Users, sessions and memories, the knowledge graph extracted from them, and recall. |
| `context-graph-viewer` | A read-only terminal viewer of the graph, opened with `memgraph-context-graph ui`. |
| `resources-graph` | GitHub issues, pull requests and repositories your agents read, so they can read them again from the graph. Off by default. |
| `context-graph-spaces` | [Shared spaces](/ai-ecosystem/ai-memory/context-graph/shared-spaces) for teams on Memgraph Enterprise. |
