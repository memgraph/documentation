# Explore the graph

Everything Context Graph records is an ordinary graph in Memgraph, so you can
look at it three ways: in the terminal viewer, in
[Memgraph Lab](/memgraph-lab), or with your own Cypher queries.

## Terminal viewer

The terminal viewer shows what your agents recorded, whether recording is
failing, and what the knowledge graph learned, without writing a query:

```bash
memgraph-context-graph ui
```

It reads the same configuration file as the hooks, refreshes every few
seconds, and never writes to the graph. Setup installs it unless you pass
`--no-viewer`.

| View | How to open it | What it shows |
| --- | --- | --- |
| Dashboard | Opens first | Your sessions, failed recordings, pending extraction and embedding work, the schema version, and new entities per day |
| Session | `enter` on a session | The session's timeline, with subagents under the call that started them, each action's input, and the entities and memory files the session produced |
| Entities | `k` on the dashboard, `g` on a session | Entities by name, by how many sessions and memory files mention them, or by most recent |
| Neighborhood | `enter` on an entity | The entity's relationships by type, with the text each one was read from. `enter` on a neighbor moves to it; `esc` goes back |

The most useful keys:

| Key | What it does |
| --- | --- |
| `a` | Show more sessions: yours, then also sessions without a user, then everyone's |
| `p` | Show one project only |
| `/` | Filter the table |
| `r` | Refresh now |
| `?` | Show all keys |
| `esc`, `q` | Go back, quit |

The viewer shows your own sessions by default. Sessions recorded before you
had a user ID belong to no user. If the dashboard is empty, press `a`.

## Memgraph Lab

To see the graph itself, connect [Memgraph Lab](/memgraph-lab) to the Memgraph
in your configuration. Print its URL with:

```bash
memgraph-context-graph config get memgraph.url
```

Connect Lab to that host and port. If you run Lab in Docker, the Memgraph
on your machine isn't at `localhost` inside the Lab container:

- **macOS and Windows:** start Lab with
  `docker run -d --name memgraph-lab -p 3000:3000 memgraph/lab:latest`, open
  `http://localhost:3000`, and connect to host `host.docker.internal`.
- **Linux:** start Lab with
  `docker run -d --name memgraph-lab --network host memgraph/lab:latest`, open
  `http://localhost:3000`, and connect to host `localhost`.

## Query the graph

The graph uses these labels and relationship types:

| Node | What it is |
| --- | --- |
| `User` | You, by `user_id` |
| `Session` | One agent session, by `session_id`, with its `project_key` and `started_at` |
| `Action` | A prompt, reply, tool call or tool result |
| `Skill` | An agent skill |
| `Memory` | A memory file, by `path` |
| `Project` | A project the memory files are about, by `key` |
| `Chunk` | A piece of a message or memory file that entities were extracted from |
| Entity labels | An extracted entity, with its name in `text`, its type in `entity_type` and a label for the type, such as `Person` |

To see every label, relationship type and property, run:

```cypher
SHOW SCHEMA INFO;
```

This needs Memgraph started with `--schema-info-enabled=true`; the Memgraph
setup starts has it.

The queries below are templates. Replace `USER_ID` with your user ID from
`memgraph-context-graph config get identity.user_id`.

Your ten most recent sessions, with the number of actions in each:

```cypher template
MATCH (:User {user_id: "USER_ID"})-[:HAD_SESSION]->(s:Session)
OPTIONAL MATCH (s)-[:HAS_ACTION]->(a:Action)
RETURN s.session_id, s.project_key, s.started_at, count(a) AS actions
ORDER BY s.started_at DESC
LIMIT 10;
```

The skills you used most:

```cypher template
MATCH (:User {user_id: "USER_ID"})-[:HAD_SESSION]->(:Session)-[:USED_SKILL]->(sk:Skill)
RETURN sk.name, count(*) AS uses
ORDER BY uses DESC;
```

Your memory files:

```cypher template
MATCH (:User {user_id: "USER_ID"})-[:HAS_MEMORY]->(m:Memory)
RETURN m.path, m.updated_at
ORDER BY m.path;
```

The sessions in which a tool was called:

```cypher template
MATCH (:User {user_id: "USER_ID"})-[:HAD_SESSION]->(s:Session)-[:HAS_ACTION]->(a:Action {tool_name: "TOOL_NAME"})
RETURN DISTINCT s.session_id;
```

The entities your sessions mention most, after you
[build the knowledge graph](/ai-ecosystem/ai-memory/context-graph/knowledge-graph):

```cypher template
MATCH (:User {user_id: "USER_ID"})-[:HAD_SESSION]->(:Session)-[:HAS_ACTION]->(:Action)
      -[:HAS_CHUNK]->(:Chunk)<-[:MENTIONED_IN]-(e)
RETURN e.text, e.entity_type, count(*) AS mentions
ORDER BY mentions DESC
LIMIT 20;
```
