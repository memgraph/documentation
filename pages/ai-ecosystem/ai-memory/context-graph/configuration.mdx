# Configure Context Graph

Context Graph keeps its settings in one configuration file. This page covers
the file, connecting to your own Memgraph, choosing what is recorded, keeping
secrets out of the graph, forgetting sessions, and updating or removing
Context Graph.

## Configuration file

Setup writes the configuration to `~/.config/context-graph/config.toml`,
readable only by you. Set the `CONTEXT_GRAPH_CONFIG` environment variable to
use another path.

The hooks read their settings only from this file, not from environment
variables, because agents run hooks without your shell's environment. Change
settings with the `config` command:

```bash
memgraph-context-graph config show
memgraph-context-graph config get memgraph.url
memgraph-context-graph config set identity.user_id alice
```

`config set` takes these keys:

| Key | Default | What it sets |
| --- | --- | --- |
| `identity.user_id` | Your git `user.name`, set by setup | Your user ID. Your sessions and memories are filed under it, and recall searches only its sessions. |
| `memgraph.url` | `bolt://localhost:7687` | The Memgraph Bolt URL |
| `memgraph.user` | Empty | The Memgraph user name |
| `memgraph.password` | Empty | The Memgraph password. `config set memgraph.password` without a value prompts for it. |
| `memgraph.database` | `memgraph` | The database, on a Memgraph with [multi-tenancy](/database-management/multi-tenancy) |
| `capture.connectors` | `skills-graph, actions-graph, sessions-graph` | What the hooks record. See [Choose what is recorded](#choose-what-is-recorded). |
| `capture.redact` | `true` | Whether secrets are redacted before they're stored. See [Keep secrets out of the graph](#keep-secrets-out-of-the-graph). |
| `capture.max_chars` | `100000` | The most characters kept from one text field, such as a tool's output. `0` keeps everything. |
| `capture.exclude_tools` | None | Tools whose calls and results aren't recorded, by name or glob |
| `capture.exclude_projects` | None | Directories in which nothing is recorded, by path or glob |
| `memory.backend` | Unset | `context-graph` when Context Graph is the agents' [memory](/ai-ecosystem/ai-memory/context-graph/recall-and-memory#use-context-graph-as-your-agents-memory). Set it with setup's `--memory-backend`, which also changes the agents' settings. |
| `session_start.resume` | `true` | Whether a session starts with the [note on where you left off](/ai-ecosystem/ai-memory/context-graph/recall-and-memory#where-you-left-off) |
| `recall.embedding_model` | `BAAI/bge-small-en-v1.5` | The embedding model for recall |
| `reconcile.auto_reconcile` | `false` | Whether the [knowledge graph](/ai-ecosystem/ai-memory/context-graph/knowledge-graph) is built after each session |
| `ontology.path` | Unset | A schema file for the knowledge graph |
| `ontology.derive` | `extend` | Whether Context Graph adds types to your schema: `extend` or `off` |
| `llm.anthropic_api_key` | Empty | An Anthropic API key, used only to learn your schema |
| `llm.openai_api_key` | Empty | An OpenAI API key, used only to learn your schema |
| `llm.derive_model` | `claude-sonnet-5-5` with Anthropic, `gpt-5` with OpenAI | The model that learns your schema |
| `edition` | `community` | `enterprise` to use [shared spaces](/ai-ecosystem/ai-memory/context-graph/shared-spaces). Set it with `memgraph-context-graph join`. |
| `github.token` | Unset | A GitHub token for `resources-graph`, used instead of your `gh` login. Prompts for the value. |

Recall's other settings, the `[extraction]` settings and `[redact]` patterns
are edited in the file directly. See [Tune recall](/ai-ecosystem/ai-memory/context-graph/recall-and-memory#tune-recall)
and [Tune extraction](/ai-ecosystem/ai-memory/context-graph/knowledge-graph#tune-extraction).

<Callout type="warning">
The file holds your Memgraph password and API keys in plain text. Setup
creates it with permissions `0600`; keep it that way.
</Callout>

## Use your own Memgraph

By default, setup starts Memgraph in Docker on your machine. To use another
Memgraph, such as a shared server or a
[high availability cluster](/database-management/clustering/high-availability),
pass its URL to setup:

```bash
memgraph-context-graph setup --memgraph-url bolt://memgraph.example.com:7687
```

If the instance has authentication, set the user and password:

```bash
memgraph-context-graph config set memgraph.user alice
memgraph-context-graph config set memgraph.password
```

For a high availability cluster, use the `neo4j://` scheme with a coordinator's
address, so the client routes writes to the MAIN instance:

```bash
memgraph-context-graph config set memgraph.url neo4j://coordinator.example.com:7687
```

The instance must run Memgraph 3.6 or later, with
[MAGE](/advanced-algorithms) for recall by meaning. To see all labels and
properties with `SHOW SCHEMA INFO`, start it with `--schema-info-enabled=true`.
The Memgraph that setup starts has it enabled.

Each user on a shared Memgraph should have their own `identity.user_id`. On a
shared Memgraph with Memgraph Enterprise, [shared spaces](/ai-ecosystem/ai-memory/context-graph/shared-spaces)
give each user a database of their own.

## Choose what is recorded

`capture.connectors` lists the packages the hooks send events to. Each one
records one part of a session:

| Connector | Records |
| --- | --- |
| `actions-graph` | Prompts, replies, tool calls and tool results |
| `skills-graph` | The agent skills a session used |
| `sessions-graph` | The session, its user and project, and memories. Recall needs it. |
| `resources-graph` | The GitHub resources a session read. Off by default. |

For example, to also remember GitHub resources:

```bash
memgraph-context-graph config set capture.connectors "skills-graph, actions-graph, sessions-graph, resources-graph"
memgraph-context-graph setup
```

Setup installs the connectors the setting names. An empty value records
nothing, without disconnecting the agents.

## Keep secrets out of the graph

The hooks record prompts, replies, and tool input and output in full, so a
session can contain an API key from a `.env` file or text you don't want
stored. Before anything reaches Memgraph, Context Graph removes what you mark
as private, redacts secrets, and shortens long text. What it removes is never
stored.

These rules apply to everything the hooks record, for every agent. They don't
apply to memory files the agent writes with the
[`memory` tool](/ai-ecosystem/ai-memory/context-graph/recall-and-memory#how-the-agent-uses-memory),
which are stored as written. Sessions recorded before an update that added the
rules stay as they were.

### Mark text as private

Text between `<private>` and `</private>` is removed from prompts, replies and
tool input and output:

```plaintext
Connect to the staging database. <private>The password is in the team vault under "staging-db".</private>
```

Context Graph stores only "Connect to the staging database.". The agent still
gets the whole prompt. If a prompt has nothing outside its private block, it
isn't stored at all. An unclosed `<private>` hides the rest of the text.

### Redact secrets

Context Graph replaces known kinds of secrets with `[REDACTED:NAME]`, where
`NAME` says what was removed:

| Name | What it matches |
| --- | --- |
| `private_key` | PEM private key blocks |
| `aws_access_key` | AWS access key IDs |
| `github_token` | GitHub tokens and fine-grained personal access tokens |
| `anthropic_key` | Anthropic API keys |
| `openai_key` | OpenAI API keys |
| `slack_token` | Slack tokens |
| `stripe_key` | Stripe secret and restricted keys |
| `google_api_key` | Google API keys |
| `jwt` | JSON Web Tokens |
| `url_password` | Passwords in URLs, such as `postgres://user:PASSWORD@host` |
| `config_secret` | The Memgraph password, API keys and GitHub token in the configuration file, if they're at least 6 characters long |

To redact your own patterns, add a `[redact]` section to the configuration
file. Each key is the name in the replacement, and each value is a
[Python regular expression](https://docs.python.org/3/library/re.html#regular-expression-syntax)
in single quotes:

```toml
[redact]
ticket = 'ACME-[0-9]+'
customer_email = '[A-Za-z0-9._%+-]+@acme\.com'
```

An invalid pattern is ignored and reported as a configuration warning, and
recording continues.

Redaction matches known shapes of secrets, so it doesn't catch every secret.
Use `<private>` or `capture.exclude_projects` for anything it might miss.

To turn redaction off, so that only `<private>` blocks are removed:

```bash
memgraph-context-graph config set capture.redact false
```

### Shorten long text

Each text field, such as a tool's output, is cut after `capture.max_chars`
characters, 100,000 by default, and ends with a note of how many characters
were removed. To change the limit, or to keep everything with `0`:

```bash
memgraph-context-graph config set capture.max_chars 20000
```

### Exclude tools and projects

To stop recording some tools' calls and results, list their names. A name can
be a glob, such as `mcp__vault__*` for every tool of one MCP server:

```bash
memgraph-context-graph config set capture.exclude_tools "TodoWrite, mcp__vault__*"
```

To record nothing from some projects, list their directories. A session that
starts in one of them, or in a directory inside one, isn't recorded. `~` stands
for your home directory, and a path can be a glob:

```bash
memgraph-context-graph config set capture.exclude_projects "~/clients/*, ~/personal"
```

The agent works as usual in an excluded project, and recall still finds your
other sessions there.

Setting a list replaces the previous one. To clear it, set an empty value:

```bash
memgraph-context-graph config set capture.exclude_projects ""
```

## Forget sessions

`forget` deletes sessions from your graph for good, with everything recorded in
them and everything extracted from them. Delete sessions by ID:

```bash
memgraph-context-graph forget session SESSION_ID
```

`SESSION_ID` is the session's `session_id`, shown in the
[terminal viewer](/ai-ecosystem/ai-memory/context-graph/explore-the-graph#terminal-viewer).
Pass several IDs to delete several sessions.

To delete every session that ran in a directory or inside it, pass the
directory:

```bash
memgraph-context-graph forget project ~/work/client-repo
```

`forget` lists the matching sessions and asks before it deletes them. Add
`--dry-run` to only list them, and `--yes` to skip the question. Without a
terminal, `--yes` is required.

For each session, `forget` deletes:

- its prompts, replies, tool calls and results, its skill uses, and its
  records of GitHub resources;
- what reconciliation extracted from it, and every entity no other session or
  memory file mentions;
- its lines in the log of failed recordings.

Entities that other sessions mention, skills, stored GitHub resources and your
memory files stay, including files the session wrote. A forgotten session
leaves only a `ForgottenSession` node with its ID, which stops a hook that is
still running, or a resumed session, from recording it again.

Only the agent's user can forget sessions: the agent has no tool for it. With
[shared spaces](/ai-ecosystem/ai-memory/context-graph/shared-spaces), `forget`
deletes from your personal space only.

## Update Context Graph

`update` upgrades the packages, then refreshes everything setup installed: the
Claude Code and Codex plugins, the hook files and MCP registrations of the
per-project agents, and the indexes and constraints in Memgraph.

```bash
memgraph-context-graph update
```

- **Choose agents** by naming them: `memgraph-context-graph update cursor`.
- **Choose projects** for the per-project agents with `--project-dir`. The
  default is the current directory.
- **Skip the upgrade** with `--no-upgrade`, to only refresh what setup
  installed.

`update` doesn't change your own hooks, the configuration file or the data in
the graph, and running it twice changes nothing. Restart running agent
sessions afterwards, because they keep the hooks they started with.

## Uninstall Context Graph

`uninstall` disconnects your agents: it removes the plugins, hook files and MCP
registrations, and turns the agents' own memory back on.

```bash
memgraph-context-graph uninstall
```

On a terminal, it then asks about each of these, and keeps it unless you
answer yes:

- **The graph:** the Memgraph container that setup started and its data
  volume, with every recorded session and memory.
- **The configuration:** the configuration file and the log of failed
  recordings.
- **The tool:** the `memgraph-context-graph` command and its packages.

To remove everything without questions, for example in a script:

```bash
memgraph-context-graph uninstall --all
```

| Flag | What it does |
| --- | --- |
| `RUNTIME ...` | Disconnect only these agents. The default is every connected agent. |
| `--project-dir DIR` | A project to disconnect the per-project agents from. Repeat it for more projects. The default is the current directory. |
| `--graph` | Also delete the graph: setup's Memgraph container and its volume |
| `--config` | Also delete the configuration file and the log of failed recordings |
| `--tool` | Also uninstall the `memgraph-context-graph` tool |
| `--all` | `--graph`, `--config` and `--tool` together |
| `--memgraph-container NAME` | The container setup started. The default is `context-graph-memgraph`. |
| `--no-tui` | Don't ask; remove the agent connections and what the flags name |

Without a terminal, `uninstall` removes only the agent connections and what the
flags name. It deletes only the container setup started, by name, never a
Memgraph you run yourself. On Windows, the running tool can't remove itself,
so `uninstall` prints the `uv tool uninstall` command to run afterwards.

<Callout type="warning">
Deleting the graph deletes everything your agents recorded, including your
memories, and can't be undone.
</Callout>
