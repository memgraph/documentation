# GraphRAG

GraphRAG retrieves the context an LLM needs by traversing a knowledge graph,
not only by matching embeddings. Vector search finds the entities a question is
about, and graph traversal follows their relationships to the facts connected
to them.

In Memgraph, a whole retrieval runs as one Cypher query: search, expansion,
ranking and prompt assembly happen inside the database. This is
[Atomic GraphRAG](/ai-ecosystem/graph-rag/atomic-pipelines).

## Retrieval pipelines

Which pipeline to use depends on the type of question:

| Question type | Where the answer is | Pipeline | Example question |
| --- | --- | --- | --- |
| Analytical | A value in the graph | [Text2Cypher](/ai-ecosystem/graph-rag/atomic-pipelines/text2cypher) | "How many organizations of each type are covered?" |
| Local | Around one entity | [Local graph search](/ai-ecosystem/graph-rag/atomic-pipelines/local-graph-search) | "What is connected to NVIDIA?" |
| Global | Across the whole dataset | [Query-focused summarization](/ai-ecosystem/graph-rag/atomic-pipelines/query-focused-summarization) | "What are the main themes overall?" |

The diagram shows the steps of each pipeline, from the question type to the
context passed to the LLM:

![A user question is routed by question type to Text2Cypher, local graph search or query-focused summarization, and each pipeline returns relevant context for the answer](/pages/ai-ecosystem/graph-rag/atomic-pipelines/atomic-graphrag-pipelines.png)

To let an agent choose the pipeline for each question, see [Agentic
GraphRAG](/ai-ecosystem/graph-rag/agentic-graphrag).

## Run the example

The command starts Memgraph and the [Memgraph MCP
server](/ai-ecosystem/integrations/mcp) in Docker, loads a knowledge graph of
finance news and runs all three pipelines on it. You need Docker and git, and
no API key.

## Build your own

1. Model your domain as a graph. See [Data modeling](/data-modeling) and
   [Model a knowledge graph](/data-modeling/modeling-guides/model-a-knowledge-graph).
2. Load your data into Memgraph. See [Knowledge graph
   creation](/ai-ecosystem/knowledge-graph-creation).
3. Create a [vector index](/querying/vector-search), a [text
   index](/querying/text-search) or both, so a query can find the entities a
   question is about.
4. Write the retrieval as a Cypher query, starting from the pipeline that fits
   your questions. See [Atomic GraphRAG](/ai-ecosystem/graph-rag/atomic-pipelines).
5. Connect your LLM or agent through the [Memgraph MCP
   server](/ai-ecosystem/integrations/mcp) or a framework such as
   [LangChain](/ai-ecosystem/integrations/langchain) or
   [LlamaIndex](/ai-ecosystem/integrations/llamaindex).

## Examples

- [GraphRAG notebook](https://github.com/memgraph/ai-demos/blob/main/graph-rag/graphRAG.ipynb):
  Builds a knowledge graph, computes embeddings and implements several
  retrieval strategies, step by step.
- [Agentic GraphRAG app](https://github.com/memgraph/ai-demos/tree/main/agentic-graph-rag):
  An agent that chooses a retrieval strategy for each question and runs vector
  search, deep path traversals, community detection and PageRank.
- [GenAI stack](https://github.com/memgraph/genai-stack): An application
  template with Memgraph, LangChain and GPT or Llama.

Case studies:

- [Precina Health](https://memgraph.com/user-stories/white-paper/memgraph-and-graphrag-transforming-diabetes-management-in-healthcare)
  uses GraphRAG on patient data for type 2 diabetes care.
- [Cedars-Sinai](https://memgraph.com/user-stories/white-paper/how-cedars-sinai-uses-memgraph-for-knowledge-driven-machine-learning)
  uses a knowledge graph and retrieval-augmented generation in Alzheimer's
  research.
