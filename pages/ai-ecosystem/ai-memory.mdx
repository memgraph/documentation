# AI memory

AI memory lets an AI system remember across sessions. In Memgraph, memory is a
graph of entities and typed relationships, so recall follows the connections
between what the system knows, what it did and what it knows how to do, not
only what sounds similar to the question.

## How Memgraph stores memory

Memgraph stores three types of long-term memory in one graph:

| Memory type | What it holds | How it's stored |
| --- | --- | --- |
| **Semantic** | What the system knows, such as facts and preferences | `(:User)-[:HAS_MEMORY]->(:Memory)` |
| **Episodic** | What the system did, such as past interactions | `(:Session)-[:HAS_ACTION]->(:Action)`, in order by `FOLLOWED_BY` |
| **Procedural** | What the system knows how to do, such as workflows | `(:Session)-[:USED_SKILL]->(:Skill)` |

The `User` and `Session` nodes are shared by all three types, so one traversal
can recall facts, past actions and skills together.

## Set up memory for your coding agents

[Context Graph](/ai-ecosystem/ai-memory/context-graph), part of the Memgraph
AI Toolkit, records the sessions of your coding agents in Memgraph as these
three types of memory, so the agents can recall them in later sessions. It
works with Claude Code, Codex, GitHub Copilot CLI, Cursor, OpenCode,
Antigravity CLI and Grok Build.

You need [Docker](https://docs.docker.com/get-docker/), unless you already run
Memgraph 3.6 or later, and a terminal. Start the setup:

<Tabs items={['Linux/macOS', 'Windows']}>
<Tabs.Tab>
```bash
curl -sSL https://install.memgraph.com/ai-memory | bash
```
</Tabs.Tab>
<Tabs.Tab>
In PowerShell 5.1 or 7:

```powershell
iwr https://install.memgraph.com/ai-memory/windows -useb | iex
```
</Tabs.Tab>
</Tabs>

The setup shows its plan and changes nothing until you confirm. It finds or
starts Memgraph, installs Context Graph and connects the agents it finds.
After that, every session of a connected agent is recorded in the graph, and
the next session can recall it.

See [Get started with Context Graph](/ai-ecosystem/ai-memory/context-graph/get-started)
for what the setup does, how to check it and how to change your choices.

## Query the memory graph

Because the three types share the `User` and `Session` nodes, one query can
answer a request such as "schedule a follow-up with the client like last
time". This query returns what the system knows about a user, their most
recent session in which a meeting was scheduled, and the skill used in it:

```cypher template
MATCH (u:User {user_id: "USER_ID"})-[:HAS_MEMORY]->(mem:Memory)
MATCH (u)-[:HAD_SESSION]->(s:Session)-[:HAS_ACTION]->(a:Action {tool_name: "schedule_meeting"})
WITH u, mem, s, a ORDER BY s.started_at DESC LIMIT 1
OPTIONAL MATCH (s)-[:USED_SKILL]->(sk:Skill)
RETURN mem.content AS client_facts, s.session_id AS last_session,
       a.timestamp AS last_meeting_at, sk.name AS skill, sk.content AS how_to
```

`USER_ID` is the user ID from the setup. To see all the labels, relationship
types and properties the memory graph uses, run:

```cypher
SHOW SCHEMA INFO;
```

The Memgraph that the setup starts has schema info enabled. If you use your
own instance, start it with `--schema-info-enabled=true`.

## Use another memory framework

If you already use an agent memory framework, you can keep it and store its
memory in Memgraph:

- [Mem0](/ai-ecosystem/integrations/mem0): Use Memgraph as the backend for Mem0
  graph memory, in Mem0 1.x.
- [Cognee](/ai-ecosystem/integrations/cognee): Use Memgraph as the graph
  database for Cognee's knowledge graph.
