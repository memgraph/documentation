# AI memory

AI memory lets an AI system use what happened in earlier sessions. In
Memgraph, memory is a graph: what the system knows, what it did and what it
knows how to do (semantic, episodic and procedural memory) are nodes linked
to the user and the session they came from.

A query can follow those links, and combine them with
[vector search](/querying/vector-search) and
[text search](/querying/text-search).

There are two ways to add this memory to an AI system:

- [Use Context Graph](#use-context-graph) for coding agents such as Claude
  Code and Codex. It records their sessions and serves them back to the
  agents, with no code to write.
- [Build your own memory](#build-your-own-memory) for your own agent or
  application. You write the memory graph from your code and query it with
  Cypher.

## Use Context Graph

Context Graph records each session of a
[supported coding agent](/ai-ecosystem/ai-memory/agents#supported-agents),
such as Claude Code or Codex, in Memgraph: your prompts, the agent's replies,
the tools it called and their results, the skills it used and the memories it
saved. In later sessions, any of those agents can read it back.

Every connected agent gets:

- **Capture.** Hooks in the agent write each session to the graph as it
  happens. You use the agent as before.
- **Recall.** A `recall` tool, served over the Model Context Protocol (MCP),
  returns what your past sessions hold about a question. Each session also
  starts with a short note on where you left off in the current project.
- **Memory**, if you turn it on. A `memory` tool replaces the agent's own
  memory, so the notes the agent saves are stored in the graph and shared by
  all your agents.

The diagram shows the three phases. During a session, the hooks capture each
event and the connectors write it to Memgraph, and the MCP server reads from
Memgraph when the agent asks. After the session,
[reconciliation](/ai-ecosystem/ai-memory/knowledge-graph) adds the knowledge
graph. Only the optional schema learning sends session text off your machine.

Context Graph is open source, part of the
[Memgraph AI Toolkit](https://github.com/memgraph/ai-toolkit/tree/main/context-graph).
By default, it stores everything in a Memgraph on your machine, with no
account or cloud service. See [Privacy](/ai-ecosystem/ai-memory/privacy) for
what is stored and how to keep things out.

To install it, see [Get started](/ai-ecosystem/ai-memory/get-started).

### How Context Graph organizes the graph

Each session is a `Session` node, linked to its `User`. Everything recorded in
the session hangs off that node:

```plaintext copy=false
(:User)-[:HAD_SESSION]->(:Session)
                         ├─[:HAS_ACTION]->(:Action)          prompts, replies, tool calls and results
                         ├─[:USED_SKILL]->(:Skill)           agent skills the session used
                         └─[:PRODUCED_MEMORY]->(:Memory)     memories the agent saved
(:User)-[:HAS_MEMORY]->(:Memory)
```

`Memory` nodes hold what the agent knows, `Action` nodes what it did, and
`Skill` nodes what it knows how to do.

Context Graph can also extract the people, organizations, projects and other
entities your sessions mention into a
[knowledge graph](/ai-ecosystem/ai-memory/knowledge-graph), linked back to the
messages they came from. Recall uses it to find facts spread over many
sessions.

## Build your own memory

To give your own agent or application a memory, write it to Memgraph from
your code and read it back with Cypher. You can use the same model as Context
Graph, shown in
[How Context Graph organizes the graph](#how-context-graph-organizes-the-graph).

### Query the memory graph

Because memories, actions and skills share the `User` and `Session` nodes,
one query can read all three. For a request such as "schedule a follow-up with
the client like last time", this query returns the user's memories, the last
session in which a meeting was scheduled, and the skills used in it:

```cypher template
MATCH (u:User {user_id: "USER_ID"})-[:HAD_SESSION]->(s:Session)-[:HAS_ACTION]->(a:Action {tool_name: "schedule_meeting"})
WITH u, s, a ORDER BY a.timestamp DESC LIMIT 1
OPTIONAL MATCH (u)-[:HAS_MEMORY]->(mem:Memory)
OPTIONAL MATCH (s)-[:USED_SKILL]->(sk:Skill)
RETURN s.session_id AS last_session, a.timestamp AS last_meeting_at,
       collect(DISTINCT mem.content) AS memories, collect(DISTINCT sk.name) AS skills
```

`USER_ID` is the user whose memory you read. To see all the labels,
relationship types and properties in the graph, run:

```cypher
SHOW SCHEMA INFO;
```

This needs Memgraph started with `--schema-info-enabled=true`.

To search memory by meaning as well as by its links, add a
[vector index](/querying/vector-search) on the memory text, and a
[text index](/querying/text-search) to search it by words.

### Use Context Graph's packages

The packages Context Graph is built from are Python libraries you can use in
your own application. `actions-graph`, `skills-graph` and `sessions-graph`
write and read memory with the model above, so your application and your
coding agents can share one memory graph. See the
[Context Graph repository](https://github.com/memgraph/ai-toolkit/tree/main/context-graph)
for each package's API.
