# Deprecated features

This section lists the configuration flags and query syntax which have been
deprecated, removed or replaced in Memgraph, and the versions where the changes
happened.

Removing a flag is a three-part process:
- From the **Deprecated in** version, the flag still works, but it is announced as going away.
- From the **Ignored from** version, Memgraph accepts the flag, but the flag has no effect.
- From the **Rejected from** version, Memgraph does not recognise the flag and fails to start if the flag is specified.

Deprecated query syntax has no **Ignored from** version: it works and returns a
`DeprecatedQuery` warning
[notification](/database-management/query-metadata#notifications) until the
**Rejected from** version.

## Currently deprecated

| Feature | Deprecated in | Ignored from | Rejected from | Replacement |
| ------- | ------------- | ------------ | ------------- | ----------- |
| `DENY DATABASE ... FROM` | 3.15 | Not applicable | Not yet | [`DENY DATABASE ... TO`](/database-management/multi-tenancy#cypher-queries-for-multi-tenancy). |
| `JSON` value of `--metrics-format` | 3.11 | Not yet | Not yet | [`--metrics-format=OpenMetrics`](/database-management/monitoring#openmetrics-monitoring). `JSON` still works, but the default changed to `OpenMetrics` in 3.13, so pass `--metrics-format=JSON` to keep it. See [Migrating from JSON to OpenMetrics](/database-management/monitoring#migrating-from-json-to-openmetrics). |

## Removed

| Feature | Deprecated in | Ignored from | Rejected from | Replacement |
| ------- | ------------- | ------------ | ------------- | ----------- |
| `--instance-down-timeout-sec` | 3.10 | 3.10 | 3.12 | [`SET COORDINATOR SETTING 'instance_down_timeout_sec'`](/database-management/clustering/high-availability/ha-commands-reference#instance_down_timeout_sec). Values are not migrated; re-apply non-default settings after upgrading. |
| `--instance-health-check-frequency-sec` | 3.10 | 3.10 | 3.12 | [`SET COORDINATOR SETTING 'instance_health_check_frequency_sec'`](/database-management/clustering/high-availability/ha-commands-reference#instance_health_check_frequency_sec). Values are not migrated; re-apply non-default settings after upgrading. |
| `--auth-module-executable` | 2.18 | 3.8 | 3.8 | [`--auth-module-mappings`](/database-management/authentication-and-authorization/auth-system-integrations#configuration-flags) |
| `--bolt-session-inactivity-timeout` | 3.3 | 3.3 | 3.8 | No replacement. Bolt sessions no longer time out on inactivity. |
| `--storage-parallel-index-recovery` | 2.13 | 2.18 | 3.8 | [`--storage-parallel-schema-recovery`](/database-management/configuration#list-of-configuration-flags), which covers indexes and constraints. |
| `--auth-module-create-missing-user` | 2.15 | 2.15 | 2.18 | Handled by the [auth module](/database-management/authentication-and-authorization/auth-system-integrations#auth-module-architecture) itself. |
| `--auth-module-create-missing-role` | 2.15 | 2.15 | 2.18 | Handled by the [auth module](/database-management/authentication-and-authorization/auth-system-integrations#auth-module-architecture) itself. |
| `--auth-module-manage-roles` | 2.15 | 2.15 | 2.18 | Handled by the [auth module](/database-management/authentication-and-authorization/auth-system-integrations#auth-module-architecture) itself. |
| `--storage-recover-on-startup` | 2.11 | 2.18 | 2.18 | [`--data-recovery-on-startup`](/database-management/multi-tenancy#configuration-flags). |
